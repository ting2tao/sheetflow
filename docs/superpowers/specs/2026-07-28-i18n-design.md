# SheetFlow 中英文国际化设计

## 目标

为 SheetFlow 增加简体中文和英文支持，使用户界面、任务状态、错误提示及 SEO 内容保持同一种语言，并让搜索引擎能够分别发现和收录两种语言的页面。

首期只支持以下语言：

- 简体中文：`zh-CN`
- 英文：`en-US`

Excel 单元格内容、工作表名称、上传文件名和生成文件名属于用户数据，始终保持原样，不参与翻译。

## URL 与语言选择

公开页面使用独立语言路径：

- `/zh/`：简体中文
- `/en/`：英文

访问 `/` 时按以下顺序选择语言并跳转到对应路径：

1. 用户此前手动选择并保存在 `localStorage` 中的语言。
2. 浏览器首选语言；以 `zh` 开头时选择 `zh-CN`，其他语言选择 `en-US`。
3. 无法读取上述信息时默认使用 `zh-CN`。

用户通过页面右上角的“中文 / EN”切换器手动切换语言。切换后应：

1. 保存语言偏好。
2. 导航到另一语言的对应路径。
3. 保留当前应用状态，包括已选择的文件、工作表、分页参数和任务进度。
4. 更新页面文案、文档语言及 SEO 元数据。

不支持的语言路径应回退到默认语言页，而不是渲染一部分已翻译、一部分未翻译的界面。

## 前端架构

使用 `vue-i18n` 作为翻译和格式化层。新增独立的国际化初始化模块，并按语言拆分资源：

```text
frontend/src/
├── i18n/
│   ├── index.js
│   └── locales/
│       ├── en-US.js
│       └── zh-CN.js
```

翻译 key 按领域组织，不按具体组件组织，以便组件拆分后仍保持稳定：

```text
app.*
upload.*
settings.*
progress.*
errors.*
seo.*
units.*
```

`App.vue` 和 `SeoContent.vue` 中的所有用户可见固定文案都改用翻译 key，包括：

- 标题、副标题和页脚
- 上传、工作表选择、设置、进度和下载区域
- 按钮、提示、占位符和浏览器弹窗
- 行、列、页和工作表等数量单位
- SEO 介绍、功能、场景、使用方法和常见问题

动态句子使用具名参数，例如页码、工作表数量和图片数量。数量相关文案使用 `vue-i18n` 的复数能力，保证英文单复数正确。

语言切换器作为独立小组件放在页面右上角。它只负责展示当前语言和发起切换，不持有业务状态。

## 路由与应用状态

当前应用没有引入 Vue Router，页面步骤也由组件内状态控制。首期不为了两个语言入口增加完整路由依赖，而是在启动时解析 `window.location.pathname`，并使用 History API 在 `/zh/` 和 `/en/` 之间切换。

这样可以：

- 保持现有单页步骤状态不变。
- 避免语言切换导致文件选择和任务进度丢失。
- 继续使用现有 Nginx 的 `try_files ... /index.html` 回退。

Vite 构建增加中文和英文两个 HTML 入口。两个入口加载同一套 Vue 应用和资源，但各自在初始 HTML 中提供正确语言的 `<html lang>`、SEO 元数据、JSON-LD 和 `<noscript>` 内容。Nginx 将 `/zh/`、`/en/` 及各自的回退路径映射到对应入口；根路径使用一个不参与索引的轻量语言选择入口。

若未来新增 `/features`、`/guide` 等内容页，再引入 Vue Router，并将路径扩展为 `/zh/features`、`/en/features`。

## 后端消息协议

后端状态值已经是稳定的英文枚举，如 `queued`、`processing`、`completed` 和 `error`，继续保留并作为前端展示状态的依据。

当前 API 的 `message` 和 `detail` 包含中文，前端不应继续将这些字符串直接作为主展示内容。任务响应改为提供：

```json
{
  "status": "processing",
  "message_code": "job.processing_sheet_page",
  "message_params": {
    "sheet_name": "Sheet1",
    "current": 2,
    "total": 5
  }
}
```

前端根据 `message_code` 和 `message_params` 本地化展示。后端可在迁移期继续返回 `message`，但只作为兼容字段；前端优先使用 `message_code`。

API 错误同样使用稳定的错误码：

```json
{
  "detail": {
    "code": "file.unsupported_type",
    "params": {
      "supported": ".xlsx"
    }
  }
}
```

业务错误由前端翻译。无法识别的错误码统一显示本地化的通用错误信息，并将服务端原始信息写入控制台供排查，避免把内部异常细节直接暴露给用户。

任务状态 JSON 只保存状态码和参数，不保存依赖某种语言的最终展示句子。这样同一任务可以在切换语言后立即显示另一种语言，而无需重新提交。

## SEO

每个语言路径必须拥有与其语言一致的：

- `<html lang>`
- `<title>` 和 description
- Open Graph 和 Twitter 元数据
- canonical URL
- JSON-LD 描述和功能列表

页面同时声明双向 `hreflang`：

```html
<link rel="alternate" hreflang="zh-CN" href="${VITE_PUBLIC_SITE_URL}/zh/">
<link rel="alternate" hreflang="en" href="${VITE_PUBLIC_SITE_URL}/en/">
<link rel="alternate" hreflang="x-default" href="${VITE_PUBLIC_SITE_URL}/zh/">
```

`sitemap.xml` 同时包含 `/zh/` 和 `/en/`，并标注对应的 alternate 链接。

生产域名通过必填的 `VITE_PUBLIC_SITE_URL` 构建变量提供；生产构建缺少该变量时直接失败，不能继续使用 `sheetflow.yourdomain.com`。本地开发默认使用 `http://localhost:3000`。

应用交互仍采用客户端渲染，但两种语言的可索引首屏文案和元数据在构建时写入各自 HTML 入口。这样无需引入 SSR，即可确保爬虫首次响应拿到语言一致的内容。若未来增加大量动态内容页，再评估完整静态站点生成或 SSR。

## 分析事件

GA4 事件名保持不变，避免切断历史数据。给 `page_view`、上传、生成和下载事件增加 `language` 参数。

语言切换单独记录：

```text
event: language_change
from_language: zh-CN
to_language: en-US
```

不得将翻译后的按钮文案或状态句子作为事件名或关键维度。

## 错误处理和回退

- 翻译 key 缺失时，开发环境输出警告。
- 生产环境先回退到 `zh-CN`，仍缺失时显示稳定的通用提示。
- 不支持的浏览器语言回退到 `en-US`。
- `localStorage` 不可用时仍可根据当前 URL 正常工作。
- API 返回旧版字符串消息时，在迁移期显示旧消息；全部接口完成迁移后移除此兼容逻辑。
- 切换语言不会中断轮询、清空表单或重新上传文件。

## 测试策略

### 单元测试

- URL、浏览器语言和已保存偏好的优先级。
- `zh`、`zh-CN`、`zh-TW`、`en` 及未知语言的映射规则。
- 状态码和错误码到翻译文案的映射。
- 动态参数与英文单复数。
- SEO 元数据生成及 canonical、`hreflang` 的对应关系。

### 组件测试

- 两种语言下主要界面均无未替换的 key。
- 切换语言后业务状态不变。
- 任务处理中切换语言，进度消息立即更新且轮询继续。
- 未知后端错误码使用本地化兜底文案。

### 构建与集成验证

- `npm run build` 成功。
- `/`、`/zh/` 和 `/en/` 在开发环境与 Nginx 部署环境均可打开或正确跳转。
- 两个语言页面的 `lang`、title、description、canonical、`hreflang` 和 JSON-LD 正确。
- sitemap 中的 URL 使用真实生产域名。
- 上传、选择工作表、生成、轮询和下载流程在两种语言下均可完成。

## 实施范围

首期包含：

- Vue 界面和 SEO 内容的中英文翻译。
- 语言 URL、自动选择、手动切换和偏好保存。
- 后端任务及错误的结构化消息码。
- 中英文 SEO 元数据、canonical、`hreflang` 和 sitemap。
- 构建时生成中文、英文和根路径语言选择入口。
- 国际化相关自动化测试和构建验证。

首期不包含：

- 中文繁体或第三种语言。
- 用户上传内容的机器翻译。
- 日期、货币或 Excel 数据格式转换。
- SSR、通用静态站点生成框架或新增内容页面。
- 按语言拆分部署。

## 验收标准

1. 用户可在 `/zh/` 与 `/en/` 访问完整、语言一致的 SheetFlow。
2. 手动切换语言不会丢失当前任务或表单状态。
3. 所有用户可见的固定文案、状态和业务错误均可翻译。
4. 两个语言 URL 具有正确且互相引用的 SEO 元数据。
5. sitemap 同时发布两种语言 URL。
6. 原有上传、解析、生成和下载功能行为不变。
7. 自动化测试覆盖语言选择、消息映射和关键切换行为，前后端现有测试与构建通过。
